# 보안과 운영 조건

[사용자 안내](../README.md) · [API 계약](API.md) · [처리 흐름](ARCHITECTURE.md)

## 게임 신원과 접근 권한

접속 중인 플레이어의 UUID와 접속 회차별 `connectionId`를 연결하고, 링크 발급과 웹 인증 요청에서 Paper 메인 스레드의 온라인 상태·`remotedatapack.manage` 권한을 검사합니다. 권한 기본값은 OP입니다.

`online-mode=true`가 기본 신원 근거입니다. 오프라인 모드에서는 웹 인증을 차단합니다. 운영자가 인증된 게임 프록시의 신원 전달과 백엔드 직접 접속 차단을 보장한 경우에만 `auth.trust-proxy-identity: true`를 사용할 수 있습니다. 이 설정 자체가 게임 프록시를 인증하거나 구성하지는 않습니다. 웹 HTTPS 프록시 사용만으로 이 값을 켤 이유는 없습니다.

토큰·세션 ID·CSRF 값·connectionId는 `SecureRandom`의 32바이트 난수로 생성합니다. 토큰과 세션 ID는 SHA-256 해시를 키로 메모리에 보관합니다. 토큰은 잠금 안에서 먼저 제거한 뒤 검증하여 동시 요청 중 한 번만 소비됩니다. 토큰을 먼저 사용한 사람이 세션을 얻으므로 링크는 비밀 정보입니다.

## 접속 수명과 작업 취소

`PlayerQuitEvent`는 해당 접속의 모든 토큰·세션을 즉시 회수합니다. 재접속은 새 connectionId를 사용하며, 이전 접속의 늦은 종료 이벤트가 새 접속을 회수하지 않도록 비교합니다. 플러그인 종료는 전체 자격 증명을 정리합니다. 웹 로그아웃은 해당 세션을, `/rdpack revoke`는 본인의 링크와 세션을 모두 회수합니다.

권한 회수는 다음 요청의 검사에서 관측됩니다. 열린 UI는 5초마다 세션을 확인합니다. 요청 사이에 권한이 회수되었다가 복구된 중간 상태까지 추적하는 계약은 아닙니다. 만료는 접근 시 단조 시계로 판정하고 링크 발급·상태 조회 시 만료 항목을 정리합니다. 연결 등록은 최대 4,096개, 접속당 미사용 링크·웹 세션은 각각 하나입니다. [쿠키·만료 설정](API.md#인증과-세션)을 함께 참조하세요.

목록·스킨·템플릿 응답과 파일 변경 직전에 접속권을 재검증합니다. I/O 워커는 세션 객체와 취소 상태를 검사하며 Bukkit API를 직접 호출하지 않습니다. 커밋 권한 예약과 quit/revoke는 같은 메모리 잠금으로 순서를 정합니다. 취소가 먼저면 변경을 막고, 예약이 먼저면 이어지는 원자 파일 작업을 소급 취소하지 않습니다. 잠금 안에서 디스크 I/O를 실행하지 않습니다. 이미 시작된 데이터 리로드도 완료까지 진행됩니다.

## 공개 주소와 HTTP 경계

`direct-http`는 외부 IP 바인딩과 HTTP 주소를, `https-proxy`는 루프백 바인딩과 HTTPS 주소를 사용합니다. 설정에 mode가 없으면 `https-proxy`로 해석합니다. 공개 주소는 scheme·host·port만 가진 origin이어야 하며 경로 접두어·사용자 정보·query·fragment를 거부합니다. `X-Forwarded-*`는 공개 주소나 권한 근거가 아닙니다.

직접 HTTP는 설정된 공개 Host·포트를 검사하며 같은 리스너의 루프백 점검도 허용합니다. HTTPS 프록시는 아래의 Host 전달 규칙을 따릅니다. 정확한 Origin·CSRF 및 쿠키 계약은 [API](API.md#공통-계약)에 있습니다. HTTP 쿠키는 포트별로 격리되지 않으므로 같은 호스트의 다른 서비스도 신뢰할 수 있어야 합니다.

| HTTP 자원 | 한도 |
|---|---|
| 활성 연결 | 64개, 응답 후 닫음 |
| 요청 헤더 | 16 KiB, 64개 |
| 연결 후 헤더 수신·워커 대기 | 절대 기한 10초, 추가 바이트로 연장되지 않음 |
| 처리 시작 후 응답 | `web.response-timeout-seconds`: 기본 10초, 1–60초 |
| HTTP 워커·대기열 | `web.workers`: 기본 4, 1–16 / `web.queue-capacity`: 기본 32, 1–256 |
| URI | raw path 2,048자, ASCII URI 4,096자 |

### HTTPS 프록시 설정

HTTPS 인증서와 TLS 종료는 리버스 프록시에서 담당합니다. 예를 들어 외부 `13532`는 프록시, 내부 `8765`는 플러그인이 사용합니다.

```text
브라우저 → HTTPS :13532 [프록시] → HTTP :8765 [플러그인]
```

```yaml
web:
  mode: https-proxy
  bind: 127.0.0.1
  port: 8765
  public-url: "https://packs.example.com:13532"
  local-development: false
```

프록시 upstream은 `http://127.0.0.1:8765`, 전달 Host는 공개 주소 또는 `localhost`로 설정합니다. 요청 크기·연결 수·헤더 시간 제한도 설정하세요. 공개 주소는 실제 브라우저의 scheme·host·외부 port와 일치해야 합니다. 외부에는 프록시 포트만 개방합니다.

`8765`는 빈 내부 포트의 예시이며 기본 포트가 자동 변경되는 것은 아닙니다. 같은 네트워크 네임스페이스의 `0.0.0.0:13532`와 `127.0.0.1:13532`는 동시에 바인딩할 수 없어 포트를 나눕니다. 별도 네임스페이스라면 같은 번호를 쓸 수 있지만, 서로 다른 Docker 컨테이너의 루프백은 서로 연결되지 않습니다. 위 예시는 프록시가 Minecraft의 루프백에 접근할 수 있는 구성을 전제로 합니다.

인증서는 접속 도메인을 포함해야 하며 포트 번호와는 무관합니다. HTTP→HTTPS 리다이렉트와 같은 포트의 HTTP·HTTPS 처리는 프록시에서 구성합니다. 기존 config의 다른 항목을 유지하고 변경 후 서버를 정상 재시작하세요.

## ZIP 검증

| 대상 | 한도 |
|---|---|
| ZIP 크기 | `packs.max-upload-mib`: 기본 20 MiB, 1–20 MiB |
| 항목 수 / 중앙 디렉터리 | 10,000개 / 4 MiB |
| 전체 비압축 크기 / 항목 압축 비율 | 선언·실제 모두 128 MiB / 100:1 |
| 루트 `pack.mcmeta` / JSON 깊이 | 64 KiB / 32 |

중앙 디렉터리와 로컬 헤더의 일치, 데이터 범위·크기·CRC, UTF-8 이름을 검증하고 스트리밍으로 실제 비압축 크기를 확인합니다. 경로 이탈·중복 이름·심볼릭 링크·특수 파일·Unix 링크 메타데이터·암호화를 거부합니다. 지원 압축 방식은 STORE·DEFLATE이며 ZIP64·다중 볼륨·아카이브 주석·허용 목록 밖 확장 필드도 거부합니다. 검사는 서버 디렉터리에 압축을 풀지 않고 수행합니다.

`pack.mcmeta`는 `pack.description`과 현재 서버 형식을 포함하는 `min_format`·`max_format`이 필요합니다. 숫자 min은 해당 major의 minor 0부터, 숫자 max는 해당 major의 모든 minor까지이며 `[major, minor]` 배열은 정확한 경계입니다. 레거시 메타데이터는 자동 변환하지 않습니다. 형식 매핑은 [개발 안내](DEVELOPMENT.md#버전-호환성)에 있습니다. 검증은 팩의 명령 실행 의미나 게임 동작의 안전성까지 보증하지 않습니다.

## 경로와 대상 보호

관리 루트는 메인 월드의 `datapacks/`로 제한합니다. `SecureDirectoryStream`과 `NOFOLLOW_LINKS`로 루트부터 각 구성요소를 열고, 실제 조작 전 루트·파일 식별자·원본 해시를 재확인합니다. ZIP 하드링크와 링크 수를 확인할 수 없는 파일은 보호합니다. Unix 링크 수 조회 결과도 디렉터리 핸들의 파일 식별자와 대조합니다. 안전한 디렉터리 핸들이나 원자적 이동을 지원하지 않는 파일시스템은 파일 관리에 사용할 수 없습니다.

Paper WORLD 출처와 안전한 로컬 ZIP이 일치하고 비필수 팩이어야 교체·다운로드할 수 있습니다. 삭제는 비활성 ZIP으로 한정합니다. 폴더·내장·플러그인·필수·미발견·위치 미확인 팩은 조작 대상에서 제외됩니다. 목록의 조작 플래그는 ZIP 내용의 유효성 보증이 아니며 실행 시 다시 검사합니다. 목록이 잘린 경우에도 대상 해석을 거부합니다. 웹 요청의 경로나 클라이언트 파일명을 저장 위치로 사용하지 않습니다.

## 백업과 복구

교체·삭제 전에 기존 ZIP을 검증하고 같은 디렉터리에 `.rd-backup-<파일명 SHA-256>-<UUID>.bak`으로 별도 복사합니다. 백업 해시 확인 후 같은 팩의 오래된 백업을 정리합니다. `packs.backup-count-per-pack`은 기본 3개(1–10), `packs.backup-max-total-mib`는 기본 200 MiB(설정된 ZIP 한도–1,024 MiB)입니다. 새 백업까지 포함해 한도를 먼저 검사하며 다른 팩의 백업을 자동으로 지우지 않습니다. 삭제 후에도 백업은 남습니다.

교체는 `SecureDirectoryStream.move()`를 사용합니다. `.rd-tmp-<UUID>.tmp`는 정상 실패 시 정리하고, 강제 종료 잔여물은 다음 실행의 첫 변경 작업에서 제한된 이름만 정리합니다. 임시·백업 파일은 팩 ZIP으로 목록에 추가하지 않습니다. 발견 갱신 실패의 보상 복구가 실패하면 `recovery_required`로 추가 파일 작업과 적용을 차단합니다.

수동 복구는 서버를 정상 종료한 뒤 대상 ZIP 파일명의 UTF-8 SHA-256에 해당하는 백업을 찾아 내용·시각을 확인하고 원래 이름으로 복사하는 절차입니다. 웹에는 백업 복원 버튼이 없습니다. 복구 후 상태를 확인하고 정상 재시작하세요.

파일 변경의 원자성은 강제 전원 종료 시 디스크 영속성이나 외부 관리자·다른 플러그인의 동시 편집까지 보장하지 않습니다. 디렉터리 쓰기 권한은 신뢰된 서버 계정에만 부여하고 외부 편집·리로드와 웹 작업을 겹치지 않게 운영합니다.

## 비밀 정보와 로그

인증 토큰은 URL fragment로 전달해 HTTP 요청·Referer에서 제외하고, UI가 즉시 제거해 동일 출처 JSON POST로 교환합니다. `no-referrer`, `no-store`, `nosniff`, 프레임 차단과 동일 출처 CSP를 적용합니다. 스킨은 서버가 공식 텍스처 서버에서 가져와 전달하므로 브라우저가 외부 스킨 서버로 접속하지 않습니다.

플러그인은 접근 로그를 생성하지 않고 HTTP 파서 오류에 URL을 반사하지 않습니다. 감사 로그에는 플레이어 UUID·작업 종류·작업 ID(파일 작업)·상태·결과 코드만 기록합니다. 프록시에서도 요청 본문·Cookie·Set-Cookie 수집을 피해야 합니다.
